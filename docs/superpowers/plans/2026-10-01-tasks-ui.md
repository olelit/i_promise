# Tamagotchi Stage 17: Task Stats, Progress and UI Consolidation — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Task history with stats, an on-screen progress bar with time-threshold comments, observer-only phrases, a bigger rectangular window, the feed button in the action row, and a «Задачи» dialog (current task + new task + history).

**Architecture:** `tamagotchi.ts` owns `TaskRecord`/`history` and the pure `taskTiming` helper; `storage.ts` normalizes old saves; `phrases.ts` gains observer phrases and milestone events; App runs the milestone state machine; new `TaskProgress`, `FeedButton` and `TasksDialog` components replace the old controls wiring.

**Tech Stack:** Vue 3.5, Vite 8, TypeScript 5.9.

## Global Constraints

- Commit messages MUST be written in English only.
- Telegram access via `src/telegram.ts`; persistence via `src/storage.ts`; no other network calls.
- `<script setup lang="ts">`, strict TS; game world uses `src/pixel/palette.ts`, native chrome the Telegram theme variables.
- At most ONE active task: `startTask` refuses to replace an active task and the «Новая задача» button is disabled while one runs.
- No new dependencies.
- No test suite: verification is `npm run typecheck` + `npm run build` plus the listed checks. The user does not review specs/plans.

### Task 1: History, timing helper, storage, i18n strings

**Files:** Modify `src/tamagotchi.ts`, `src/storage.ts`, `src/i18n.ts`.

**Interfaces produced:**
- `TaskStatus = 'done' | 'abandoned' | 'overdue'`;
  `TaskRecord = { description, hours, startedAt, finishedAt, status }`.
- `HISTORY_MAX = 20`, `TASK_MILESTONE_FRACTION = [0.5, 0.25]`,
  `TASK_MILESTONE_SOON_MS = 600_000`.
- `TamagotchiState.history: TaskRecord[]`; `taskTiming(task, now): { elapsed, total, remaining, overdue }`.
- `storage.ts` normalizes a missing/malformed history to a valid capped array.
- `i18n.ts`: `formatDuration(ms)`, `formatDateTime(ts)`, and the new message keys (`tasks`, `newTask`, `noActiveTask`, `historyTitle`, `historyEmpty`, `statusDone`, `statusAbandoned`, `statusOverdue`, `progressOf`, `overdueFor`, `planLabel`, `factLabel`, `hoursShort`).

**Behavior:**
- `completeTask` appends `{ status: 'done', finishedAt: now }`; `abandonTask`
  appends `'abandoned'` (mood 0); the `applyDecay` overdue branch appends
  `'overdue'` with `finishedAt = task.deadline`. All append through a helper
  that prepends and slices to `HISTORY_MAX`.
- `startTask` returns the state unchanged when `state.task !== null`.
- Every literal state return (four `applyDecay` branches, `feed`, `startTask`)
  carries `history: state.history`.
- `taskTiming`: `total = deadline - startedAt`, `elapsed = clamp(now - startedAt, 0, total)`, `remaining = max(0, deadline - now)`, `overdue = max(0, now - deadline)`.

**Steps:**
1. Implement the `tamagotchi.ts` changes (types, constants, helpers, appends, guards).
2. Implement `storage.ts`: `isValidRecord` type predicate, `normalizeHistory(value): TaskRecord[]` (filter invalid, clamp description to `TASK_DESCRIPTION_MAX`, `hours` to `[TASK_MIN_HOURS, TASK_MAX_HOURS]`, slice to `HISTORY_MAX`), call it in `normalizeState`.
3. Implement the `i18n.ts` keys and helpers (`formatDuration` rounds to minutes, uses `hoursShort` when the remainder is 0; `formatDateTime` is `DD.MM HH:MM` for ru and `M/D HH:MM` for en).
4. Verify: `npm run typecheck`, `npm run build`; local Vite SSR script exercising `completeTask`/`abandonTask`/overdue append, the 20-cap, `startTask` refusal, and `taskTiming` (import `src/tamagotchi.ts` via `server.ssrLoadModule` from `/tmp` with `root: process.cwd()`, like the earlier webhook test).
5. Commit: `Add task history, timing helper and storage normalization`.

### Task 2: Observer phrases and milestone comments

**Files:** Modify `src/phrases.ts`, `src/App.vue`.

**Interfaces:**
- New events `taskHalf`, `taskQuarter`, `taskTenMinutes` in `PhraseEvent` and `PHRASES` (ru/en).
- App milestone state machine using `taskTiming`, `TASK_MILESTONE_FRACTION`, `TASK_MILESTONE_SOON_MS`.

**Behavior:**
- Rewrite all task phrases so the pet only watches: e.g. `taskStart` —
  «Понял, слежу за временем», «Записал. Удачи!», «Буду ждать»; `taskComplete` —
  «Ты успел! Отлично», «Готово. Молодец!», «Справился!»; `taskExtend` — «Продлил?
  Посмотрим», «Время добавлено», «Ещё час в запасе»; `taskAbandon` — «Жаль, но
  бывает», «Ладно, отменили», «В другой раз»; `overdue` — «Время вышло...»,
  «Не успел...», «Срок истёк»; plus the three milestone events. Feed/greeting/
  away phrases stay. English translations mirror the same observer tone.
- App: a `milestones` ref `{ startedAt, half, quarter, soon }`.
  - `checkMilestones(announce)`: when the task's `startedAt` differs from the
    tracked one, initialise the flags from the CURRENT remaining time without
    announcing; otherwise, per check, announce only the most urgent newly
    crossed threshold (`soon` > `quarter` > `half`) when `announce` is true,
    then store the current crossed state (so an extension that raises the
    remaining time re-arms the flags).
  - Call with `announce: true` from `tick()` and on `visibilitychange` becoming
    visible; call with `announce: false` after starting/extending/completing/
    abandoning a task.
  - Thresholds: `remaining <= total * 0.5`, `remaining <= total * 0.25`,
    `remaining <= TASK_MILESTONE_SOON_MS`.

**Steps:**
1. Rewrite `phrases.ts` (events + ru/en).
2. Add the milestone machine to `App.vue` and the call sites.
3. Verify typecheck/build; local check that a task whose remaining crosses 0.5
   announces once and not again on the next tick.
4. Commit: `Make the pet observe the task and comment on time left`.

### Task 3: Progress bar, feed button and the tasks dialog

**Files:**
- Create `src/components/TaskProgress.vue`, `src/components/FeedButton.vue`,
  `src/components/TasksDialog.vue`
- Delete `src/components/TaskInfoDialog.vue`
- Modify `src/components/MoodControls.vue`, `src/App.vue`, `src/i18n.ts`

**Interfaces:**
- `TaskProgress` props `{ task: TamagotchiTask; now: number }`; renders the thin
  pixel bar (frame/bevel/track like `MoodIndicator`, ~14 px) and the label
  «X из Y» / «Просрочено на X»; blue `PALETTE.O` fill, red `PALETTE.r` when
  overdue. Presentational only (the parent decides whether it is clickable).
- `FeedButton` props `{ nextFeedMs: number | null; blockReason: 'cooldown' |
  'full' | null }`, emits `feed` / `feedBlocked`; carries the label, disabled
  state, haptic and blocked-phrase logic moved from `MoodControls`.
- `TasksDialog` props `{ task: TamagotchiTask | null; now: number; history:
  TaskRecord[] }`, emits `complete`, `extend`, `abandon`, `newTask`, `close`.
  Sections: current task (description, progress, the three actions with the
  two-tap abandon confirm), «Новая задача» (disabled while a task is active),
  history (status label, `план N ч`, `факт X`, date) with an empty state.

**Behavior:**
- Main screen: `<TaskProgress>` under the mood indicator, wrapped in a button
  that opens the tasks dialog; hidden when there is no task.
- Bottom action row is ALWAYS rendered: browser — «Задачи», «Скины»,
  «Покормить»; Telegram — `MainButton` «Задачи», `SecondaryButton` «Скины»,
  in-app row holds «Покормить» (and «Скины» when there is no secondary button).
- `MoodControls.vue` keeps only the away message (drop the feed button and its
  props/logic).
- `MainButton` label is «Задачи»; its click opens the tasks dialog (with the
  existing guard while another dialog is open).
- «Новая задача» in the dialog closes it and opens `TaskCreateDialog`;
  starting a task closes the create dialog and syncs the milestone flags.

**Steps:**
1. Create the three components and update `MoodControls.vue`.
2. Rewire `App.vue` (replace `infoOpen` with `tasksOpen`, the row, the main
   screen progress button, the dialog, the MainButton label/click); delete
   `TaskInfoDialog.vue`.
3. Add any missing `i18n.ts` keys (e.g. dialog section labels).
4. Verify typecheck/build; screenshots: progress bar with a task, tasks dialog
   with history, feed in the row.
5. Commit: `Replace the task dialogs with progress, stats and one action row`.
